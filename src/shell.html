Codebook

Each variable is one question per article and one column in your data. Outlet, country, date, headline, pages and coder are recorded for you, so leave them out.

Import a codebook

Load a Word (.docx) or text codebook, or a codebook file someone shared from Chota (.json). Chota reads numbered variables such as V3 ELIGIBLE with their codes, codes like 97 and 98, skip instructions such as "If 0, stop" or "skip to V9", and checks such as "V9 must be one of the framings coded 1 in V6 to V8". You can check everything before it loads.

Questions

Skipped and missing codes

When a skip rule applies, the skipped questions are filled with the not-applicable code in your data, so they stay separate from questions a coder left empty. Missing-value codes are kept in the data but marked as missing in SPSS, and set to NA in the R and Python files, so they drop out of percentages and models.

Reasons for excluding an article

Chota asks for one of these whenever an article is excluded, by the Exclude button or by a skip rule. One per line. The reason is exported with the article, ready for a sample flow table.

Share the codebook

Download the codebook as a file that other coders import here. Locking it stops anyone editing questions or codes by accident, so everyone codes with the same version. Each coded article also records the version it was coded with.

Paste a codebook

One question per line as name | question | type | coding rule | skip: rules. Types are binary (Yes 1, No 0), single: 0=No; 1=Yes; 98=Cannot determine, number or text. Skip rules are optional, for example skip: 0=exclude (end coding and exclude the article), 0=end or 0=dominant (skip to that question). You can also paste a codebook written as numbered variables. Pasting replaces the list above.

Reliability

Report Krippendorff's alpha for each variable. An alpha of .80 or higher is the usual benchmark, and .667 is the floor for tentative conclusions. Alpha uses each question's measure (nominal, ordinal or scale). The 95% interval comes from 1,000 resamples of the articles. Skipped questions and missing-value codes are left out.

Compare coders

Load the other coders' codes files: each coder's chota-codes-name.json from a shared folder, or a backup they downloaded from Export. Articles coded by two or more coders are compared, including yours.

Recode a sample yourself

With one coder, reliability comes from coding a random subsample twice. Wait about a week, then recode the sample without seeing your first codes.

Settings

All optional. A target and deadline show your progress and daily pace above the coding sheet.

Outlets

One per line as Outlet name = Country. Chota looks for these names on each article's first page and in file names, and fills in the outlet and country for you. The order sets the numeric codes, so the first outlet is 1. Outlets you type in while coding are numbered after these.

Sampling log

Import the spreadsheet of sampled articles (.xlsx or .csv, one row per article). Chota matches each article to its row by headline or PDF file name. It fills in the outlet, country, date, year and headline from columns with those names, and fills any question whose name matches a column (for example ARTICLE_ID). Every column of the log is added to your exports.
